# 길드 공유 백엔드 (Cloudflare Worker)

길드원들이 같은 데이터를 보게 해주는 서버예요. 카운터덱·영웅·가이드·공성전/파괴신 기록을
Cloudflare KV에 저장하고, 캡처 판독(`/ocr`)과 라운지 공략 학습(`/learn`)도 여기서 돕니다.

**외부 API 키가 필요 없습니다.** AI 작업은 전부 Cloudflare Workers AI로 돌아갑니다.
(예전 'AI 공략검색' 기능은 2026-07-14에 제거됐습니다.)

**시크릿은 하나 있습니다 — `ADMIN_PW`** (워커 최고권한, 관리자를 전부 잃었을 때의 복구 수단).
예전 문서는 '시크릿을 쓰지 않는다' 고 적고 있었는데 코드는 쓰고 있었습니다. 사람이 외울 만한
비번이 아니라 **긴 난수**로 두세요 — 시도 제한은 IP 단위라 긴 난수가 진짜 방어입니다.

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
npx wrangler secret put ADMIN_PW      # 위에서 나온 값을 붙여 넣는다
```

> 옛 소프트 관리자 비번의 SHA-256(솔트 없음)이 **공개 저장소 이력에 남아 있습니다.**
> 같은 값을 `ADMIN_PW` 로 쓰고 있었다면 반드시 바꾸세요.

## 배포 (운영진 본인이 한 번만)

이 `worker` 폴더에서 순서대로 실행하세요. (`npx`라 따로 설치 안 해도 돼요.)

```bash
# 1) Cloudflare 로그인 (브라우저 창이 뜸 — 없으면 무료 가입)
npx wrangler login

# 2) 공유 데이터 저장용 KV 만들기 → 출력된 id 를 wrangler.toml 의 [[kv_namespaces]] id 에 붙여넣기
#    (이미 id가 채워져 있으면 건너뛰세요 — 새로 만들면 기존 데이터와 끊깁니다)
npx wrangler kv namespace create GUILD_KV

# 3) 배포
npx wrangler deploy
```

마지막에 `https://sena-guild-search.<계정>.workers.dev` 주소가 출력돼요.
그 주소를 `src/data/config.ts` 의 `WORKER_URL` 에 넣고 사이트를 재배포하면,
길드원 전원이 별도 설정 없이 같은 데이터를 봅니다.

> 사이트 배포(`./deploy.ps1`)와 워커 배포는 **별개**예요.
> 이 폴더 파일을 고친 날은 `npx wrangler deploy` 를 따로 실행해야 반영됩니다.
>
> **순서: 워커 먼저, 사이트 나중.** 새 사이트는 워커가 응답 헤더 `x-save-merge: 1` 로
> '보낸 칸만 합친다' 고 알려 줄 때만 바뀐 칸만 보냅니다(아니면 예전처럼 전체를 보내므로
> 순서가 어긋나도 데이터는 안 사라집니다). 다만 새 관리 화면의 관리자 체크박스·모든 기기
> 로그아웃·강제 로그아웃은 새 워커에만 있어서, 사이트를 먼저 올리면 그동안 오류가 납니다.
>
> 호출 제한(`[[ratelimits]]`)에는 **wrangler 4.36 이상**이 필요합니다. 바인딩이 빠져도 워커는
> 돌지만(로그인 제한은 옛 KV 방식으로 떨어진다), 새 보호가 대부분 꺼지니 배포 로그의
> 바인딩 목록에 `RL_AUTH`·`RL_CRED`·`RL_WRITE`·`RL_AI` 가 보이는지 확인하세요.

## 엔드포인트

아래 '누가'는 로그인 검사가 켜진 상태 기준입니다.

| 메서드 | 경로 | 하는 일 | 누가 |
|---|---|---|---|
| `GET`  | `/data` | 공유 데이터 조회 | 길드원 (운영진 전용 칸·변경 기록은 빼고 내려감) |
| `POST` | `/data` | 공유 데이터 갱신 `{data}` — **보낸 칸만** 직전 저장본에 합친다 | 길드원 (허용된 칸만) / 운영진은 전부 |
| `GET`  | `/data/prev` | 직전 백업본 (10분에 1번) | **운영진** |
| `GET`  | `/data/daily` | 가장 최근 일별본 · `?list=1` 날짜 목록 · `?day=YYYY-MM-DD` 그날 것 (14일 보관) | **운영진** |
| `POST` | `/ocr` | 캡처에서 점수·순위 판독 (사람마다 분당 15장·하루 60장) | 길드원 |
| `POST` | `/learn` | 라운지 새 공략 수집·분류·요약 | **운영진** |
| `GET`  | `/learn/latest` | 마지막 학습 결과 + cron 실행 기록 | **운영진** |
| `GET`  | `/api/siege?week=&day=` | 공성전 통계 | **운영진** |
| `GET`  | `/api/destroyer?season=` | 파괴신 통계 | **운영진** |
| `POST` | `/auth/login` | 닉네임+비번 → 토큰 | 누구나 |
| `POST` | `/auth/password` | 내 비번 바꾸기 (8자 이상·지금 비번과 달라야 함, 새 토큰을 같이 돌려줌) | 로그인한 사람 (명단에 있어야) |
| `POST` | `/auth/logout-all` | 내 계정의 모든 기기에서 로그아웃 (세션 버전을 올린다) | 로그인한 사람 |
| `POST` | `/auth/list` | 명단·권한·발급 현황·마지막 로그인·관리 기록·이름 중복 | 사이트 관리자 |
| `POST` | `/auth/issue` | 임시 비번 발급 (7일 유효, 영구 관리자는 시크릿만) | 사이트 관리자 |
| `POST` | `/auth/revoke` | 아이디 해제 (그 토큰도 죽는다) | 사이트 관리자 |
| `POST` | `/auth/kick` | 강제 로그아웃 — 비번은 두고 토큰만 끊는다 (영구 관리자는 시크릿·본인만) | 사이트 관리자 |
| `POST` | `/auth/admins` | 사이트 관리자 지정 `{add:[], remove:[]}` — 바뀐 것만 (옛 `{ids}` 도 받음) | 사이트 관리자 |
| `POST` | `/auth/enable` | 로그인 검사 켜기 / **끄기는 영구 관리자·시크릿만, 24시간 뒤 자동 복구** | 사이트 관리자 |

오류 응답의 `code`: `login`(401) · `gone`·`mustchange`(403, 로그인 화면으로) · `bulk`(403, 대량 삭제) ·
`rate`(429, 잠시 뒤 다시) · `daily`(429, 오늘 한도) · `kv`(503, KV 쓰기 실패 — 보통 하루 한도).
검증에 걸린 저장은 `field` 로 어느 칸 때문인지 알려 줍니다(화면은 그 칸만 되돌리고 나머지 편집은 다시 보낸다).

`/auth/*` 는 **POST 만** 받습니다. 사이트 관리자 자리는 두 갈래로 엽니다 —
로그인한 사이트 관리자 토큰, 또는 워커 시크릿 `ADMIN_PW`(헤더 `x-admin-pw`,
base64). 후자는 관리자를 전부 잃었을 때의 복구 수단입니다.

> **⚠ `src/data/config.ts` 에 비밀을 두지 마세요.** 예전엔 여기 `ADMIN_PW_HASH`
> (솔트 없는 SHA-256)가 있었는데, 정적 번들은 통째로 공개되므로 받아서 오프라인으로
> 깨면 그만이고 같은 값을 워커 시크릿으로도 쓰고 있어서 워커 최고권한까지 넘어갔습니다.
> 지웠습니다. 관리자 판정은 워커에 물어봅니다(`src/auth.ts`).
> 자세한 규칙은 저장소 루트 `CLAUDE.md` 의 '보안' 절이 정본입니다.

## 자동 학습 루틴 (cron)

**매일 06:00 KST**에 워커가 스스로 라운지를 학습합니다. 사람이 사이트를 열지 않아도 돌아요.
스케줄은 `wrangler.toml` 의 `[triggers] crons` — Cloudflare는 UTC 기준이라 `0 21 * * *` 입니다.

```toml
[triggers]
crons = ["0 21 * * *"]   # 21:00 UTC = 06:00 KST
```

한때 홈 화면의 브리핑을 누가 열어야만 학습이 돌았는데, 그 UI를 내리면서 **트리거가
하나도 안 남아 학습이 조용히 멈춰 있었습니다.** 같은 일이 다시 안 생기도록:

- 실행할 때마다 KV `learn-cron` 에 결과를 남기고, `GET /learn/latest` 가 같이 내려줍니다.
- 운영진 [데이터] 페이지 브리핑 위에 마지막 실행 시각이 뜨고,
  **이틀 넘게 안 돌면 빨간 경고**로 바뀝니다.

운영진 [데이터] 페이지의 `[🔭 새 글 학습]` 버튼은 그대로 있어요 — 루틴을 기다리지 않고
지금 돌리고 싶을 때 씁니다.

> **신규 영웅 판별에는 영웅 로스터가 필요합니다.** cron에는 브라우저가 없어서, 운영진이
> 버튼으로 학습할 때 보낸 목록을 KV `learn-heroes` 에 캐시해 두고 그걸 씁니다.
> 캐시가 아직 없으면 요약은 정상으로 돌고 **신규 영웅 판별만 건너뜁니다** —
> 로스터를 모르는 채로 판별하면 아는 영웅까지 전부 "신규"로 뜨기 때문이에요.
> 워커를 처음 배포했다면 [데이터] 페이지에서 한 번만 버튼을 눌러 로스터를 채워 주세요.

## 안전장치

- **로그인 게이트** — KV `auth-on`:
  `'1'` 켬 / `'0'` 끔(**영구 관리자·시크릿만**, 기한 `until` 이 붙고 **24시간 뒤 KV 가 스스로 지운다**) /
  없음 → 아이디가 하나라도 있으면 **켬**, 하나도 없을 때만 끔. 예전엔 `'1'` 이 아니면 전부 꺼진 걸로
  봐서 키 하나가 사라지면 사이트가 인터넷에 열렸습니다. 모르면 닫습니다.
  처음 명단을 심을 때는 **첫 아이디를 만드는 순간 켜지므로**, 먼저 시크릿으로 끈 뒤(24시간) 발급하세요.
- **권한 두 축** — 게임 안 직책(`길드마스터`·`부길드마스터` = 운영진)과 사이트 관리자
  (KV `site-admins`)는 별개입니다. 자격을 주는 판정은 **항상 명단 확인과 짝**입니다
  (`guard` 의 `findMember`, `handleAuth` 의 `meMember`). 이 짝을 깨지 마세요 —
  빠졌을 때 길드를 나간 옛 관리자가 토큰이 사는 30일 동안 전권을 유지했습니다.
- **영구 관리자(`owner-id`)** — 명단에서 뺄 수 없습니다. 비번 재발급은 워커 시크릿만
  가능합니다(재발급은 곧 그 계정 인수라서).
- **토큰** — HMAC 서명 + 30일. 안에 그때의 비번 갱신 시각(`a`)과 세션 버전(`v`)이 들어 있어,
  비번을 바꾸거나 아이디를 해제하거나 **모든 기기 로그아웃·강제 로그아웃**하면 그 전 토큰이 전부 죽습니다.
- **계정** — 새 비번 8자 이상·지금 비번과 달라야 함. 임시 비번은 **7일** 뒤 만료. 임시 비번 상태의
  토큰은 데이터 경로(`guard`)도 관리자 경로(`/auth/*`)도 안 받습니다.
- **호출 제한 (`[[ratelimits]]`, KV 를 안 쓴다)** — `/auth/*` 전체 IP 당 분당 30 · 비번 맞춰 보기
  (로그인은 `IP(/64)+닉`, 비번 변경은 계정, 워커 시크릿은 IP) 분당 5 · 저장은 사람당 분당 60 ·
  AI 는 사람당 분당 15. IPv6 는 주소가 아니라 /64 로 묶습니다.
  **KV 로 세지 마세요** — 예전 로그인 제한은 시도마다 KV list·put 을 해서, 계정 없이 약 1,000번이면
  그날(UTC) 로그인과 **모든 저장**이 멈췄습니다(KV 무료 한도: 하루 쓰기·list 각 1,000회).
  바인딩이 없을 때만 옛 KV 방식으로 떨어집니다. (워커 주소가 `*.workers.dev` 라 대시보드의 존 단위
  Rate Limiting 규칙은 걸 곳이 없습니다)
- **KV 하루 쓰기 한도 지키기** — 일반 길드원 저장 하루 150회, 비번 변경·모든 기기 로그아웃 하루 20회,
  캡처 판독 하루 60장, 마지막 로그인 기록은 1시간에 한 번만 씀, 안 바뀐 저장은 안 씀.
- **크기 제한** — `POST /data` 는 1MB 초과 시 거부 (실데이터는 수십 KB 수준).
  `content-length` 가 없어도 상한까지만 읽고 끊습니다(`/auth/*`·`/ocr`·`/learn` 도 같다).
- **형식 검증** — 칸마다 담는 원소 종류(객체/문자열 id), 필수 배열 키(없으면 `[]` 로 채움),
  중첩 배열의 빈 원소(`null`), `updatedAt` 문자열까지 봅니다. 깨진 데이터 하나면 전 길드원 화면이
  죽고 '로컬 비우고 새로고침' 으로도 안 낫습니다.
- **저장은 '보낸 칸만 합치기'** — 운영진 저장도 직전 저장본 위에 보낸 칸만 얹습니다. 옛 사본이
  다른 사람의 변경을 되돌리거나 빈 점수 칸이 기록을 덮는 사고를 막습니다. 명단을 통째로 비우는
  저장, 이름이 겹치는 길드원, 영구 관리자의 개명(본인 외)은 거부합니다.
- **대량 삭제 차단** — 일반 길드원은 한 번에 3개, 하루 60개(서로 다른 항목)까지만 지우거나 바꿉니다.
  '지우지 않고 비우기' 와 '기본 카운터와 같은 id 로 빈 항목 넣기(가리기)' 도 셉니다.
- **기록** — 저장마다 누가·언제·어느 칸·몇 개 +/−/~ 인지 저장본의 `_log`(최근 100건, 운영진만 봄)에,
  관리자 행동(재발급·해제·지정·검사 끄기·강제 로그아웃)은 KV `audit-auth` 에 남깁니다.
  `wrangler.toml` 의 `[observability]` 로 워커 로그도 켰습니다.
- **버전(`_rev`)** — KV는 최종 일관성이라 오래된 데이터가 읽힐 수 있어요.
  서버가 스탬프한 rev로 비교해 최신 편집이 덮어써지지 않게 합니다.
- **백업** — `/data/prev`(10분) · `/data/daily`(하루, **날짜별 14일 보관**). 백업을 못 쓰면 저장도
  멈춥니다(덮어쓰기 전 상태를 잃지 않게). 사고 나면 여기서 복구하세요.
- **브라우저 밖 push 차단** — `src/store.ts` 가 `window` 없는 환경(Node 등)과 localhost에서는
  업로드를 무조건 막습니다. 실제로 Node 테스트가 전 길드 데이터를 덮어쓴 사고가 있었어요
  (2026-08-14, 백업으로 복구). **이 가드를 우회하지 마세요.**

## 비용

Workers AI 무료 할당량(하루 10,000뉴런) 안에서 동작하도록 맞춰져 있어요.

- `/learn` 은 10분에 1번으로 제한되고, 한 번에 새 글 6개 · 글당 이미지 3장까지만 읽습니다.
  진단 분기(`debugFeedId`)도 사람마다 분당 제한을 받습니다.
- `/ocr` 은 사람마다 분당 15장·하루 60장(`OCR_DAILY`). 넘으면 화면이 브라우저 판독으로 넘어갑니다.
- 할당량이 부족하면 `worker.js` 의 `LEARN_MAX_POSTS` · `LEARN_MAX_IMAGES` 를 줄이세요.

`sec-test.mjs`(보안 회귀) · `role-test.mjs`(권한 반영)는 로컬 워커에 대고 돕니다. **운영 주소로는 안 돌게**
막혀 있습니다(데이터를 덮어씁니다).

```bash
npx wrangler dev --local --port 8799 --var ADMIN_PW:testpw
node sec-test.mjs <실행마다 다른 글자>   # 다시 돌릴 땐 1분 뒤에 — 계정 단위 호출 제한이 실행을 넘어 이어진다
node role-test.mjs <실행마다 다른 글자>
node client-test.mjs <실행마다 다른 글자> # 실제 src/store.ts 를 번들해 저장 프로토콜(바뀐 칸만·옛 워커 호환·거절 복구)을 본다
```
